# LaPrint — 의료기기 라벨 출력 프로그램

의료기기(스텐트) 라벨을 라벨DB에서 불러온 값으로 조판해 **PDF** 또는 **ZEBRA 프린터(ZPL)** 로 출력하는
**Windows 프로그램(C# / .NET 8 / WPF)** 입니다. 설치가 필요 없고, 모든 데이터는 이 PC에만 저장됩니다.

UDInspect(UDI 바코드 검사) · LaVis(라벨 검사)와 같은 구조(WPF + Core 라이브러리 + xUnit)와
색·타이포·HFE 체계를 따르는 패밀리 프로그램입니다.

```
UDInspect   UDI 라벨을 읽어 검사한다   (검사)
LaVis       라벨 인쇄물을 검사한다     (검사)
LaPrint     라벨을 만들어 출력한다     (출력)
```

## 실행 (Windows)

1. GitHub **Releases › Latest Build** 에서 `LaPrint-win-x64-latest.zip` 을 받아 폴더에 풉니다.
2. `LaPrint.exe` 를 실행합니다. .NET 설치가 필요 없는 단일 실행 파일입니다 (Windows 10 이상, x64).
3. 처음 실행하면 안내창이 뜹니다. **[샘플 데이터로 체험]** 을 누르면 동봉된 샘플 DB와 제품 그림으로
   폴더 지정 없이 바로 써 볼 수 있습니다. 실제로 쓰실 때는 ⚙ 설정 › 폴더 경로에서
   라벨DB 폴더·파일(`01.라벨출력DB.xls`, `02.라벨출력DB_BSC.xls`), 이미지 폴더, PDF 저장 폴더를 지정합니다.

> 네트워크 폴더는 `\\서버\공유\...` UNC 경로를 그대로 지정할 수 있습니다 (브라우저판과 달리 드라이브 연결이 필요 없습니다).
> 설정·서식·출력 이력은 `%APPDATA%\LaPrint\` 에 저장됩니다. 문제가 생기면 같은 폴더의 `app.log` 를 보내 주세요.

### 소스에서 빌드

```
# .NET 8 SDK 필요 (Windows). 리눅스/CI 에서도 컴파일·Core 테스트는 가능합니다.
dotnet test csharp/tests/LaPrint.Core.Tests -c Release      # 골든 테스트
dotnet run --project csharp/src/LaPrint.App -c Release      # 실행 (Windows)
dotnet publish csharp/src/LaPrint.App -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o csharp/publish   # 단일 exe
```

GitHub Actions(`.github/workflows/build-csharp.yml`)가 windows-latest 에서 테스트 → 단일 exe → zip → `latest-build` 릴리스를 자동으로 만듭니다.

> **브라우저판(레거시)** — `index.html` 을 Chrome/Edge 로 열면 같은 기능의 브라우저 버전이 실행됩니다.
> C# 판은 이 브라우저판을 그대로 옮긴 것이며, 브라우저판이 실제 라벨DB로 계산한 기준값을 골든 테스트로 삼아 동일함을 검증합니다.

## 화면 구성

모드가 없습니다. 라벨 1장을 만드는 화면과 50장을 만드는 화면이 같고, 차이는 아래 큐에 행이 쌓였는지뿐입니다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 앱바   서식 · 잠금 · 실물보기 ·············· DB/이미지/저장폴더 칩 · ⚙ │
├────────────┬────────────────────────────────────┬────────────────────┤
│ 작업 입력  │  캔버스 (입력하면 즉시 반영되는    │ 속성 / 객체 트리   │
│ DB 참조값  │   실제 미리보기 · 눈금자 · 스냅)   │ 자간·커닝·행간     │
│ 출력 점검  │                                    │ 어간·장평          │
│ [출력]     │                                    │ 데이터 링크        │
├────────────┴────────────────────────────────────┴────────────────────┤
│ 연속 작업 큐 (비어 있으면 접힌 상태 = 1장 작업)                       │
├──────────────────────────────────────────────────────────────────────┤
│ 상태바  잠금상태 │ [시각] 메시지 │ 배율 │ 저장 시각                    │
└──────────────────────────────────────────────────────────────────────┘
```

### 단일 작업 (라벨 1장)

품목번호 입력 → LOT 입력 → `Ctrl+P`. **조작 3회**로 끝납니다.
제조일은 오늘 날짜가 미리 채워져 있고, 유효일은 `EDATE(제조일, 개월) − 1일`로 자동 계산됩니다.

### 연속 작업 (여러 장)

큐를 채우는 방법 4가지 — 어느 쪽이든 조작 횟수가 **건수와 무관**합니다.

| 방법 | 조작 |
|---|---|
| 엑셀에서 복사한 표 붙여넣기 | 큐에서 `Ctrl+V` → 열 매핑 확인 → 확인 |
| CSV/XLSX 파일 불러오기 | [파일 불러오기] |
| 현재 입력을 한 줄씩 쌓기 | `Ctrl+Enter` (LOT만 비워지고 포커스 유지) |
| SN 연번 전개 | 행 선택 → [SN 연번…] → 1~100 → 100행 |

각 행은 실시간으로 검증되어 대기/오류 상태가 표시되고, 오류 행은 출력에서 자동으로 제외됩니다.
출력 중 일시정지·중지가 가능하며, 완료된 행은 파일명이 표시됩니다.

## 주요 기능

### 데이터

- **라벨DB 로딩** — `.xlsm / .xlsx / .xls / .csv`. H열(품목번호)이 조회 키.
  시트 이름과 무관하게 데이터가 가장 많은 시트를 자동으로 고릅니다.
- **자동 로딩** — 설정에서 DB 폴더와 파일명을 지정해 두면 프로그램을 열 때 자동으로 읽고,
  파일이 바뀌었을 때만 다시 읽습니다(12,000행 재파싱 생략).
- **품목 검색** — 품목번호·규격·제품명으로 즉시 검색. ↓/Enter로 확정.
- **출고 구분 (DB 프로필)** — 작업 입력 맨 위에서 고릅니다.
  | 구분 | 쓰는 파일 | 비고 |
  |---|---|---|
  | 일반 | `01.라벨출력DB` | 기본값 |
  | BSC 출고 (일본) | `02.라벨출력DB_BSC` | AL열부터 열 구성이 다름 |

  파일 · 열 매칭 · 조회 키 · 캐시가 구분마다 따로 관리됩니다.
  BSC를 고르면 입력 영역에 주황색 **BSC** 표시가 붙어, 평소와 다른 DB를 쓰고 있음이 드러납니다.

### 데이터 매칭 편집기

라벨DB를 **별도 창에 표로 펼쳐 놓고** 각 항목이 읽을 열을 직접 지정합니다.

- 왼쪽 — 항목 목록(규격·GTIN·제품명 …)과 조회 키. 열 문자를 직접 입력해도 됩니다.
- 오른쪽 — 열 문자 / DB 머리글 / 실제 값 6줄. 열을 클릭하면 선택한 항목에 배정됩니다.
  지금 고른 품목이 맨 윗줄에 오므로 값을 보면서 고를 수 있습니다.
- 텍스트·바코드 식·그림 슬롯에서도 **[DB 열 직접 고르기…]** 로 그 자리에서 열을 지정합니다
  (텍스트·바코드에는 `{@열}` 로 들어가고, 그림 슬롯은 그 열의 값을 파일명으로 읽습니다).

**열 매칭 점검** — 실제 라벨DB의 머리글 줄은 예전 양식이 남아 값과 맞지 않는 곳이 있습니다.
그래서 머리글이 아니라 **실제 값을 표본으로 확인해** 알려 줍니다.

- 표본 전체가 빈 열 → 오류
- 값이 거의 없는 열(20% 미만) → 경고
- 그림 항목인데 값이 파일명이 아닌 경우 → 오류 (`그림파일 없음` 같은 메모가 들어 있는 행)

### 라벨DB 품질 확인

실제 DB(12,199행)에서 확인된 것들을 로딩 시점에 걸러 내고 알려 줍니다.

- 품목번호가 비었거나 `0` 인 행은 색인에서 제외 (실제 194행). 넣어 두면 `0` 을 입력했을 때
  엉뚱한 제품이 나옵니다.
- 같은 품목번호가 여러 번 나오면 **먼저 나온 행**을 쓰고, 몇 종이 겹쳤는지 알려 줍니다.
- 그림 파일은 **대소문자를 가리지 않고** 찾습니다. 라벨DB에는 `E.JPG` · `e.JPG` · `E.jpg` 가
  섞여 있는데, Windows 공유 폴더와 달리 브라우저는 대소문자를 구분하기 때문입니다.

### 조판 (한글 조판 표준 용어)

| 항목 | 설명 | 범위 |
|---|---|---|
| **자간** | 글자와 글자 사이 간격 | −5 ~ 30 pt |
| **커닝** | 글자 쌍별 자동 간격 보정 (AV, To 등) | 켬 / 끔 |
| **어간** | 낱말과 낱말 사이 간격 | −10 ~ 60 pt |
| **행간** | 줄과 줄 사이 간격 | 0.4 ~ 6 배 |
| **장평** | 글자의 가로 비율 | 10 ~ 500 % |

그 밖에 글꼴·크기·굵게·기울임·색·가로세로 정렬·자동 줄바꿈·**자동 축소**(영역을 넘치면 크기를 줄임)를 지원합니다.
한글은 글자 단위로, 영문은 낱말 단위로 줄바꿈하며 줄 앞 금칙 문자를 처리합니다.

> 조판 계산은 mm 단위로 한 번만 하고 그리기만 배율을 곱하므로, **화면과 PDF의 레이아웃이 일치합니다.**
> (실측 오차 0.024mm)

### 데이터 링크 시각화

라벨 한 장에는 같은 값이 여러 곳에 반복해 찍힙니다. 기본 서식에서는 UDI가 12곳, LOT·REF·SN이 각 11곳입니다.
한 곳만 고치고 다른 곳을 빠뜨리는 실수를 막기 위해 세 가지로 보여 줍니다.

- **링크 보기** (툴바) — 켜 두고 **객체를 하나만** 고르면, 같은 값을 쓰는 다른 자리가 주황으로 표시되고
  선택한 객체 위에 `LOT · 11곳` 이름표가 붙습니다. 화면이 어지러워지지 않도록 한 번에 하나만 보여 줍니다.
- **속성 패널** — "LOT {LOT} · 11곳" 목록. 클릭하면 그 데이터를 쓰는 객체가 모두 선택됩니다.
- **직접 링크** — 바코드가 다른 객체의 텍스트를 참조하면 보라색 화살표로 이어집니다.

### 바코드

| 심볼로지 | 용도 |
|---|---|
| GS1 DataMatrix | UDI 표준 (의료기기) |
| GS1-128 | 물류·포장 1D |
| DataMatrix / Code 128 / QR | 자유 텍스트 |

데이터를 묶는 방법 3가지:

1. **DB/계산 필드** — `UDI_FULL`, `GTIN01`, `LOT` 등에서 바로
2. **직접 입력** — `(01){GTIN}(10){LOT}` 처럼 자유 조합
3. **다른 객체의 텍스트 링크** — 캔버스의 특정 객체를 지목해 그 내용을 그대로 바코드로 (순환 참조 차단)

검증: GTIN 체크디짓, AI 길이·형식, 날짜 형식, 모듈 크기(권장 최소 0.254mm), GS1-128 최소 높이.
모듈이 정수 픽셀이 되도록 배율을 역산해 그리므로 리샘플링으로 판독이 깨지지 않습니다.

### 출력

**PDF** — 기본은 **라벨 실물 크기(mm) 그대로** 1장씩. 저장 폴더 지정, 파일명 규칙(`{ITEM}_{LOT}_{DATE}` 등),
이름 충돌 시 번호 자동 증가. 개별 파일 또는 한 PDF에 여러 쪽.

**용지 배치 (면付)** — 선택 사항입니다. `인쇄 크기` 에서 A4·A3·Letter 등을 고르면
같은 용지에 라벨을 여러 개 앉혀 인쇄합니다. 여백·간격·정렬·재단선·테두리선을 지정할 수 있고,
몇 열 몇 행이 들어가는지 미리 보여 줍니다. 연속 출력은 칸을 서로 다른 라벨로 채웁니다.

**라벨 규격** — 원본 A3 원판(297×420mm)에 모여 있던 12종을 실측해 프리셋으로 넣었습니다.
`원판에서 떼기…` 를 누르면 원판에서 그 라벨만 잘라 **그 크기의 독립 서식**으로 만듭니다
(배경 서식 그림도 해당 부분만 잘라 옵니다). 기본 서식은 `PMFL-001 대형 라벨 173.8×75mm` 입니다.

**ZEBRA 프린터 (ZPL)** — 라벨을 프린터 해상도의 흑백 그림으로 바꿔 `^GFA` 그래픽 명령으로 보냅니다.
화면·PDF와 **완전히 같은 그림**이 찍히고, 프린터에 한글 글꼴을 올릴 필요가 없습니다.

- 전송: **Zebra Browser Print**(권장) · **USB 직접 연결**(WebUSB) · **.zpl 파일 저장**
- 설정: 해상도(203/300/600dpi), 농도, 속도, 용지 처리, 180도 회전, 흑백 변환 기준값, 디더링
- 진단: 테스트 라벨(DataMatrix 포함) · 설정 라벨 인쇄 · 용지 캘리브레이션
- ZPL 표준 ASCII 압축을 적용해 전송량을 줄입니다 (기본 서식 기준 약 4.5배)

### 출력 전 검증 (오류 방지)

잘못된 라벨이 제품에 붙으면 환자 안전 문제가 됩니다. 출력 전에 자동으로 검사하고,
**오류가 있으면 출력 버튼이 비활성화**됩니다.

| 심각도 | 항목 |
|---|---|
| 차단 | 품목번호 없음 / DB에 없는 품목 / LOT 없음 / 제조일 없음 / GTIN 체크디짓 오류 / 유효일이 제조일보다 빠름 / 바코드 생성 실패 |
| 경고 | 유효일 지남 / 이미지 누락 / 치환되지 않은 `{항목}` / 텍스트 넘침 / 라벨 밖 객체 / 바코드 모듈 크기 / 큐 내 중복 |

출력 직전에는 품목·규격·LOT·SN·제조일·유효일·UDI를 크게 다시 보여주고 미리보기 썸네일과 함께 확인받습니다.

### 편집기

휠 줌(커서 기준) · 스페이스 드래그 패닝 · 빈 곳 드래그로 사각형 선택 · 눈금자 · 격자 ·
**맞춤 안내선(스냅)** · 실행취소/다시실행 · 정렬 6종 · 균등 분배 · 크기 맞춤 ·
잠금/숨김 · z-order · 복제 · 복사/붙여넣기 · 객체 트리.

**레이아웃 잠금**(기본 켬)이 있어 현장 작업자가 실수로 객체를 움직일 수 없습니다.
`Ctrl+L`로 해제하면 편집자가 되고, 상태바에 경고가 표시됩니다.
`F5`(실물 보기)는 편집 보조선을 감추고 인쇄될 모습만 보여 줍니다.

### 그 밖에

- **이미지 배경 자동 투명화** — 투명 PNG는 그대로, JPG·불투명 PNG는 가장자리에서 이어진 배경만 제거
- **출력 이력** — 언제/무엇을/몇 장 출력했는지 기록, CSV 내보내기 (품질기록용)
- **서식 저장** — 이름 붙여 여러 개 저장, JSON 내보내기/가져오기
- **자동 저장** — 레이아웃·입력값·큐가 IndexedDB에 저장되어 브라우저를 닫아도 이어집니다
- **다크 모드** — 시스템 설정 따름 / 밝게 / 어둡게

## 원본 엑셀과의 대응

이 프로그램은 기존 엑셀 매크로 파일(`.xlsm`)의 수식과 VBA를 그대로 옮긴 것입니다.

| 엑셀 | LaPrint |
|---|---|
| `=EDATE(D1,36)-1` | 유효일 자동 계산 (말일 클램프 포함) |
| `=INDEX(라벨DB!L:L, MATCH(B1, 라벨DB!H:H, 0))` | 품목번호 조회 → DB 참조값 |
| `=B6&"(10)"&B2&"(17)"&F2&…` | UDI 조합 (빈 AI 그룹은 생략) |
| VBA `GenerateBarcode` (bwip-js 웹 API 호출) | bwip-js 내장 — 오프라인 동작 |
| VBA `UpdateImagesKeepAspectRatio` + `ImgConfig` 시트 | 이미지 슬롯 (종횡비 고정 · 위치 저장) |
| 프린터 출력 | PDF / ZEBRA ZPL |

## 알려진 제약

- ZPL은 그래픽 전송 방식이라 순수 텍스트 명령보다 전송량이 큽니다. 일반 데스크톱 모델의 최대 인쇄 폭(약 104mm)을 넘는
  라벨은 산업용 모델이 필요합니다.
- **BSC 출고(일본)** 는 DB 쪽만 준비되어 있습니다. 파일·열 매칭·조회 키·캐시는 구분마다 따로 관리되고
  기본 열 매칭도 실제 값을 확인해 넣어 두었지만, **BSC 전용 라벨 서식(레이아웃)은 아직 만들지 않았습니다.**
  BSC DB에만 있는 `UPN` · `Catalog or Ref #` · `스텐트구분` · `형명(일본/말레이시아)` 은 필드로 준비되어 있어
  서식에서 `{UPN}` 처럼 바로 쓸 수 있습니다.
- 브라우저판(레거시)은 Chrome·Edge 에서만 폴더 연동이 되고 재시작 후 [다시 연결]이 필요합니다. C# 판에는 해당 없음.
